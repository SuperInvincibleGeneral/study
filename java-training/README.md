# Java 新人研修：自力で調べて解決する課題集（全20問）

## この課題集の目的

**AI に聞かずに、自分でキーワードを選び、インターネットで調べて解決できるようになること。**

実装内容が分からないとき、ビルドエラー・コンパイルエラー・実行時エラーが出たとき、
「何を手がかりに」「どんな言葉で調べ」「どの情報を信じるか」を自分で決められるようになるのが到達点です。

コードを直すこと自体は目的ではありません。**調べ方を身につけることが目的** です。
そのため各課題には「検索ログ」の記入欄があり、**何を検索したかの記録も提出物** になります。

---

## ルール

1. **生成AI（ChatGPT / Claude / Copilot / IDE のAI補完 など）を使わない。**
   使ってよいのは検索エンジン、公式ドキュメント（Javadoc）、技術記事、書籍、公式のエラーメッセージ。
2. **先に `solution/` を見ない。** 解答例は、自力で通してから答え合わせに使う。
3. **1問につき、詰まったら最長60分。** 60分で解けなければ検索ログを埋めた状態で先輩に相談する。
   「何が分からないか」「何を調べたか」を説明できる状態で相談すること。
4. **検索ログを必ず埋める。** 空欄のまま提出された課題は未提出扱い。
5. `test/` と `common/` は編集しない。編集してよいのは `work/` だけ。

```
java-training/
├── run.sh / run.bat        テスト実行スクリプト
├── common/Assert.java      答え合わせ用の検証ヘルパー（編集禁止）
└── exNN-テーマ/

    ├── work/               ★ここを編集する
    ├── test/               答え合わせ用テストコード（編集禁止）
    └── solution/           解答例（自力で通すまで開かない）
```

1. `exNN-.../README.md` を読む
2. `work/` の中のソースを編集する
3. テストを実行する

   Linux / macOS:
   ```
   ./run.sh 01
   ```
   Windows:
   ```
   run.bat 01
   ```
4. `[FAIL]` が 0 件になったらクリア
5. クリアしてから `solution/` を開き、自分の答えと見比べる。
   **解答例のコメントには「なぜそうするか」が書いてあります。ここが一番の学びどころです。**

解答例だけを動かして確認したいとき:
```
./run.sh 01 solution
```

## 検索の作法（この研修で身につけてほしいこと）

### 1. エラーは「上から1件目」だけを読む
コンパイルエラーは1件目が原因で、2件目以降はその巻き添えであることがほとんどです。
1件目を直してから、もう一度コンパイルする。

### 2. `ファイル名:行番号: error: 内容` の形を読む
```
Greeting.java:9: error: ';' expected
```
→ `Greeting.java` の **9行目**。まずそこを開く。

実行時エラー（スタックトレース）も同じ。**一番上の `at ...(ファイル名:行番号)`** が落ちた場所です。

### 3. 検索キーワードから「自分だけの固有名詞」を外す
自分が付けたクラス名・変数名を入れると、世界中の誰ともヒットしません。

| | 検索キーワード |
|---|---|
| ✕ | `Greeting.java incompatible types scores` |
| ○ | `java incompatible types int cannot be converted to String` |

### 4. 英語のまま検索する
Java のエラー文は英語のほうが圧倒的に情報量が多い。**訳さずにそのまま貼る。**
理解できないときだけ、和訳を調べる。

### 5. 「現象に名前が付いていないか」を疑う
- 1個ずれる → **off-by-one error**
- 桁があふれる → **overflow**
- ループ中に消すと落ちる → **ConcurrentModificationException**
- 例外を握りつぶす → **exception swallowing**
- 太ったインターフェース → **fat interface**

**名前が分かれば検索は9割終わり** です。分からない現象に出会ったら、
まず「この現象は何と呼ばれているか」を調べてください。

### 6. 一次情報を優先する
1. **公式 Javadoc**（`docs.oracle.com`）… そのメソッドが何を返し、いつ例外を投げ、null を返すか
2. **公式チュートリアル / JLS**
3. Stack Overflow（**採用された回答だけでなくコメント欄も読む**。古い回答は要注意）
4. 個人ブログ（**書かれた年を必ず見る**。Java 8 時代の情報が今も最善とは限らない）

「`java <クラス名> javadoc`」で検索して公式ページを開く習慣をつけてください。

### 7. 検索の前に「観察」する
```java
System.out.println("i=" + i + " list=" + list);
```
の1行で分かることが、30分の検索より速いことがよくあります。
**何が起きているかを目で見てから、言葉にして、検索する。**

### 8. 先輩に聞く前のチェックリスト
- [ ] エラーメッセージの1行目を読んだか
- [ ] 落ちた行を開いて、そこの変数の値を出力して確認したか
- [ ] 固有名詞を外したキーワードで検索したか
- [ ] 英語のまま検索したか
- [ ] 公式 Javadoc を見たか
- [ ] 「自分は何を分かっていないか」を1文で言えるか

最後の項目が言えれば、質問の8割は自己解決しています。
