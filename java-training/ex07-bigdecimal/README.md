# 課題07: 金額計算と BigDecimal（難易度 ★★★☆☆）

## この課題のねらい
「なんとなく動いているが、たまに1円ずれる」タイプの不具合を扱う。
**症状（1円ずれる）から原因（2進浮動小数点）へ、検索でたどり着く** 練習をする。

## 状況
`work/PriceCalculator.java` は金額を計算するクラス。経理から次の指摘が来ている。
- 合計金額の末尾に `0.30000000000000004` のような値が出る
- 税込金額が1円ずれることがある
- `1.10` と `1.1` が「違う金額」と判定される
- 人数で割ると例外が出ることがある

## 仕様（テストが期待する動き）
| メソッド | 仕様 |
|---|---|
| `sum(String...)` | 合計を **小数第2位** の `BigDecimal` で返す（例: `0.1 + 0.2` → `0.30`） |
| `taxIncluded(amount, rate)` | 税込金額。**1円未満は切り捨て**、小数部を持たない値 |
| `sameAmount(a, b)` | `"1.10"` と `"1.1"` は **同じ金額** として true |
| `perPerson(amount, people)` | 1人あたり。**小数第2位で四捨五入** |

## 手順
1. `work/PriceCalculator.java` を編集する
2. `./run.sh 07` （Windows は `run.bat 07`）

## 制約
- `test/` と `common/` は編集しない
- **`double` / `float` を一切使わないこと。** すべて `BigDecimal` で計算する
- 戻り値の型は `BigDecimal` のまま

## 自力で調べるためのポイント
- テスト実行時に `(参考) 0.1 + 0.2 = ...` が出力される。**まずその値を見る。**
  想像と違う値が出たら、それが検索の出発点。
  - 例: `java 0.1 + 0.2 0.3 にならない 理由`
  - 例: `浮動小数点数 誤差 2進数 なぜ`
- `BigDecimal` を使えば解決、ではない。**`BigDecimal` にも落とし穴が3つある。**
  1. `new BigDecimal(0.1)` と `new BigDecimal("0.1")` は結果が違う → なぜか調べること
  2. `equals` と `compareTo` の結果が食い違う → なぜか調べること
  3. `divide` が例外を投げる → 例外名で検索すれば答えが出る
- 検索のコツ: **例外名 + クラス名** が最強の組み合わせ。
  - 例: `java BigDecimal divide ArithmeticException Non-terminating decimal expansion`
- 「切り捨て」「四捨五入」を Java で何と呼ぶかは `RoundingMode` の Javadoc に全部載っている。
  日本語の用語（切り捨て・切り上げ・四捨五入）と英語の定数名を対応付けてメモしておくこと。
