# 課題09: 繰り返し中の削除（難易度 ★★★☆☆）

## この課題のねらい
- 例外が出るバグ（`ConcurrentModificationException`）
- **例外が出ないのに結果が間違うバグ**（インデックスずれ）

この2つを同時に扱う。後者は「例外名で検索」が使えないので、
**現象を自分の言葉で表現して検索する** 力が試される。

## 状況
`work/TaskList.java` には3つの不具合がある。**種類の違う例外が2つ出るので、1つずつ順に直すこと。**
1. 初期タスクを渡して生成したリストを変更（add / remove）すると例外が出る
2. 1 を直すと、今度は `removeDone()` が **別の例外** で落ちる
3. `removeShorterThan()` は例外は出ないが、**消えるはずのタスクが残る**（一番厄介なのはこれ）

## 仕様（テストが期待する動き）
| メソッド | 仕様 |
|---|---|
| `new TaskList("A", "B")` | 初期タスク付きで生成。**生成後も add / remove できる** |
| `removeDone()` | `"[x]"` で始まるタスクを **すべて** 削除 |
| `removeShorterThan(n)` | n 文字未満のタスクを **すべて** 削除（連続していても漏らさない） |

## 手順
1. `work/TaskList.java` を編集する
2. `./run.sh 09` （Windows は `run.bat 09`）

## 制約
- `test/` と `common/` は編集しない
- `try-catch` で例外を握りつぶすのは禁止
- `removeShorterThan` は **`removeIf` 以外の方法**（`Iterator` を使う書き方）でも一度書いてみること。
  両方書いてみて、コメントにどちらを選んだか理由を書くこと

## 自力で調べるためのポイント
- **例外が出るバグ**: 例外名をそのまま検索する。ただし「回避方法」だけコピーせず、
  **なぜ起きるのか（modCount とは何か）** まで読むこと。
  - 例: `java ConcurrentModificationException なぜ 起きる`
  - 例: `java リスト ループ中 削除 正しい方法`
- **例外が出ないバグ**: 現象を短い日本語 or 英語にしてから検索する。
  - 「1個飛ばしで消える」→ `java list remove ループ インデックス ずれる`
  - デバッグの基本として、ループの中で `System.out.println(i + " : " + tasks)` を入れて
    **毎回の状態を目で見る**こと。検索の前に観察。
- **`UnsupportedOperationException`**: 「なぜ add できないリストがあるのか」を調べる。
  - 例: `java Arrays.asList add できない`
  - 例: `java 固定長リスト 可変リスト 違い`
  - `List.of(...)` も同じ性質を持つ。あわせて確認しておくこと。
