# 課題08: `String#split` は正規表現（難易度 ★★★☆☆）

## この課題のねらい
**「使っている API の引数が何者なのか」を Javadoc で確認する** 習慣をつける。
`split` の引数は「区切り文字」ではない。そこに気づけるかどうかがすべて。

## 状況
`work/CsvParser.java` はテキストを分割するクラス。次の不具合が報告されている。
- ドット区切りにしたら、結果が空の配列になる
- パイプ区切りにしたら、1文字ずつに分割される
- `"a,b,,"` を分割すると要素が2個しか返ってこない
- 区切り文字をユーザーが指定できるようにしたら、括弧を指定したときに例外が出る

## 仕様（テストが期待する動き）
| 入力 | 期待する結果 |
|---|---|
| `splitByDot("2024.05.01")` | `["2024", "05", "01"]` |
| `splitByPipe("A\|B\|C")` | `["A", "B", "C"]` |
| `splitCsv("a,b,,")` | `["a", "b", "", ""]` （**末尾の空項目も残す**） |
| `splitBy("a(b", "(")` | `["a", "b"]` （区切り文字を **正規表現として解釈させない**） |

## 手順
1. `work/CsvParser.java` を編集する
2. `./run.sh 08` （Windows は `run.bat 08`）

## 制約
- `test/` と `common/` は編集しない
- 自前で1文字ずつ走査して分割する実装は禁止。**`split` を正しく使って解くこと**
- `splitBy` は **どんな区切り文字が来ても** 動くこと（呼び出し側は正規表現を知らない前提）

## 自力で調べるためのポイント
- まず `String#split` の Javadoc を開く。引数名が何になっているか **英単語をそのまま読む**。
  - `java 21 String split javadoc`
- 引数の正体が分かったら、次の問いはこうなる。
  - 「`.` や `|` は正規表現でどういう意味か？」→ `正規表現 メタ文字 一覧`
  - 「特殊文字をただの文字として扱うには？」→ `正規表現 エスケープ` / `java 正規表現 リテラル 扱う`
- 末尾の空要素が消える件は Javadoc の `limit` の説明にはっきり書いてある。
  **エラーが出ないバグは、Javadoc を読むしかない。** 検索より先に一次情報を読む練習。
- `splitBy` は「実行時に決まる文字列を、正規表現ではなくそのままの文字として扱いたい」という要求。
  この要求に対応する標準メソッドが `java.util.regex` にある。
  - 例: `java 正規表現 文字列を リテラルとして 扱う メソッド`
