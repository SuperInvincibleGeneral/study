# 課題03: static と インスタンスの境界（難易度 ★★☆☆☆）

## この課題のねらい
`non-static ... cannot be referenced from a static context` は、
「エラー文の日本語訳」だけ調べても直せない。**static の意味そのもの** を調べる必要がある。
「エラー文で検索 → 概念の説明にたどり着く → 自分のコードに当てはめる」という流れを体験する。

## 状況
`work/Counter.java` はコンパイルが通らない。さらに `createdCount()` の仕様も満たしていない。

## 仕様（テストが期待する動き）
- `count` は **インスタンスごとに独立** する。`a` を増やしても `b` は変わらない。
- `doubled()` は `count` の2倍を返す。**インスタンスメソッド** にすること。
- `createdCount()` は **これまでに生成された `Counter` の総数** を返す。
  `a.createdCount()` と `b.createdCount()` は必ず同じ値になる。
- `main` は `count = 2` と出力できること。

## 手順
1. `work/Counter.java` を編集する
2. `./run.sh 03` （Windows は `run.bat 03`）

## 制約
- `test/` と `common/` は編集しない
- `doubled()` / `createdCount()` の **メソッド名と戻り値の型** は変えない
- フィールドは `private` のままにすること

## 自力で調べるためのポイント
- 検索キーワードの作り方: エラー本文から **固有名詞（count, increment）を外す** と汎用的な解説に当たる。
  - ○ `java non-static variable cannot be referenced from a static context`
- 概念を調べるときは「エラー名」ではなく **「何が違うのか」** を問いの形にする。
  - 例: `java static フィールド インスタンス フィールド 違い`
  - 例: `java static メソッド いつ使う`
- 「インスタンスごとの値」か「クラス全体で1つの値」か、を **日本語で言い切れるか** を自分に問うこと。
  言い切れないうちはコードを書き始めない。
