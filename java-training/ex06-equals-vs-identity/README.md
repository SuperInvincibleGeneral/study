# 課題06: `==` と `equals` / Integer キャッシュ（難易度 ★★☆☆☆）

## この課題のねらい
**「自分の環境では動くのに、本番で落ちる」** 種類のバグを扱う。
テストが通っているのに本番で落ちるとき、何を疑い、どう検索するかを学ぶ。

## 状況
`work/Membership.java` は会員照合クラス。開発中は問題なかったが、
- 会員IDが 1000 番台の人だけ「別人」と判定される
- CSV から読み込んだ名前が、画面に入力した同じ名前と一致しない

という不具合が上がってきた。テストを実行すると、`★ここが本番` と書かれた行が落ちる。

## 仕様（テストが期待する動き）
| メソッド | 仕様 |
|---|---|
| `sameId(a, b)` | 値が同じなら true。両方 null なら true、片方だけ null なら false |
| `sameName(a, b)` | 同上 |
| `contains(names, target)` | 同じ内容の文字列があれば true。target が null でも落ちない |
| `sameNameIgnoreCase(a, b)` | 大文字小文字を無視して比較。null 安全 |

## 手順
1. `work/Membership.java` を編集する
2. `./run.sh 06` （Windows は `run.bat 06`）

## 制約
- `test/` と `common/` は編集しない
- `sameNameIgnoreCase` は `toUpperCase()` して比較する実装をやめ、専用のメソッドを探して使うこと

## 自力で調べるためのポイント
- **なぜ 100 では通って 1000 で落ちるのか？** この「境界がありそうな挙動」に気づけるかが山場。
  境界を自分で二分探索して特定してから検索すると、キーワードが一気に絞れる。
  - 例: `java Integer == 128 以上 false`
  - 例: `java Integer cache -128 127`
- **なぜリテラルなら通って、組み立てた文字列だと落ちるのか？**
  - 例: `java String == 比較 ダメ 理由`
  - 例: `java 文字列 定数プール intern`
- 「null が来ても落ちない比較」を1行で書く方法が標準ライブラリにある。
  - 例: `java null 安全 equals 標準 メソッド`
- 大文字小文字を無視した比較も専用メソッドがある。`String` の Javadoc のメソッド一覧を上から眺めること。
